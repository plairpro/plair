# Счётчики ленты игр

Маленький Cloudflare Worker: считает, сколько раз игру запускали и сколько
ей поставили лайков. Лента `plair.pro/games` спрашивает у него числа и по
ним строит сортировку «Популярное».

## Что он хранит

Три числа на игру — запуски, лайки, комментарии — и случайный номер
браузера. Номер браузер выдал сам себе и держит у себя; он нужен ровно
для двух вещей: не дать накрутить запуски перезагрузкой страницы и не
дать лайкнуть одну игру дважды. По нему нельзя узнать человека, и дальше
счётчиков он никуда не идёт. Ни имён, ни почты, ни адресов, ни кук.

## Почему D1, а не KV

У Workers KV на бесплатном тарифе не только тысяча записей в сутки, но и
**одна запись в секунду на ключ**. Счётчик запусков одной игры — это
ровно один ключ, так что на геймджеме записи начали бы теряться. У D1 на
том же бесплатном тарифе 100 000 записей строк в сутки и 5 млн чтений, а
`plays = plays + 1` никакого потолка на строку не имеет.

## Как поднять

```sh
cd worker
npx wrangler login
npx wrangler d1 create plair-counts      # id из вывода вписать в wrangler.toml
npx wrangler d1 execute plair-counts --remote --file=./schema.sql
npx wrangler deploy
```

Деплой напечатает адрес вида `https://plair-counts.ИМЯ.workers.dev`.
Его нужно вписать одной строкой в `games/games.js`:

```js
var COUNTS = 'https://plair-counts.ИМЯ.workers.dev';
```

Пока там пусто, лента работает как раньше: сортировка «Популярное»
показывает тот же порядок, что и «Новое», и честно говорит об этом.

## Что он умеет

| запрос | что делает |
|---|---|
| `GET /counts` | все счётчики разом, минута кэша |
| `GET /mine?visitor=…` | какие игры этот браузер лайкнул |
| `POST /play` `{id, visitor}` | засчитывает запуск, но не чаще 10 раз в сутки с браузера на игру |
| `POST /like` `{id, visitor, on}` | ставит или снимает лайк, один с браузера на игру |

Чужие домены Worker не обслуживает, и игру принимает только ту, что есть
в `games.json`, — иначе в таблицу насыплют выдуманных имён.
