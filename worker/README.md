# Счётчики и комментарии ленты игр

> Актуальное и полное описание сервера — в закрытой документации проекта (раздел BACKEND). Этот файл — история первой установки; шаги ниже уже выполнены.

Маленький Cloudflare Worker с базой D1. Лента `plair.pro` берёт у него
числа для сортировки «Популярное» и комментарии к играм.

## Как поднять

Один скрипт, запускать в Terminal на Mac:

```sh
cd ~/Documents/plair/site/worker
./setup.sh
```

Он по шагам:

1. входит в Cloudflare (откроется браузер);
2. создаёт базу `plair-counts` и таблицы;
3. публикует Worker и показывает его адрес `https://plair-counts.ИМЯ.workers.dev`;
4. спрашивает ключи входа через Google и GitHub — и прямо там же пишет,
   где их взять и какой адрес возврата указать;
5. спрашивает ваш ник на GitHub (модератор) и токен Telegram-бота
   (уведомления о новых комментариях) — оба шага можно пропустить;
6. вписывает адрес Worker’а в `games/games.js`.

После этого сайт нужно опубликовать (commit + push). Пока адрес не вписан,
лента работает как раньше: кнопок комментариев нет, «Популярное» совпадает
с «Новым».

Скрипт можно запускать повторно — например, чтобы добавить вход через
GitHub позже. База и ключ подписи пропусков второй раз не создаются.

Можно и без скрипта, мышкой в панели Cloudflare: создать базу D1
`plair-counts`, создать Worker `plair-counts`, вставить код из
`src/worker.js`, привязать базу под именем `DB` и добавить переменную
`GOOGLE_CLIENT_ID`. Таблицы и ключ подписи Worker создаст себе сам при
первом запросе.

### Вход через Google

Работает на публичном Client ID — секретный ключ Google не нужен.
Кнопка «Sign in with Google» отдаёт странице подписанный Google’ом
паспорт, Worker проверяет подпись по открытым ключам Google и что паспорт
выписан именно нашему Client ID. В Google Cloud у клиента типа Web
application должны быть указаны Authorized JavaScript origins
`https://plair.pro` и `https://www.plair.pro`.

## Что хранится

**Счётчики.** Запуски, минуты в игре, лайки, репосты, сохранения и число
комментариев на игру, плюс случайный
номер браузера, который тот выдал себе сам, — чтобы запуски не накручивали
перезагрузкой. По нему нельзя узнать человека.

**Комментарии.** Текст, игра, время и автор. Об авторе — только имя и
аватар (то, что видно под комментарием) и его номер у Google или GitHub.
Почту не просим, пароли и ключи Google/GitHub не храним: после входа у
браузера остаётся наш собственный подписанный пропуск на 180 дней.
Кнопка «Delete my comments and account» стирает всё о человеке разом.

Комментарий весит около полукилобайта. На бесплатном тарифе D1 — 5 ГБ
места и 100 000 записей в сутки: это миллионы комментариев, и в GitHub
они не попадают вовсе.

## Формула «Популярного»

```
очки = запуски + минуты в игре + 5 × лайки + 8 × комментарии + 10 × репосты + 10 × сохранения − 2 × скипы
```

Считает сама лента (`score()` в `games/games.js`, веса — в `WEIGHT`),
Worker только отдаёт числа через `/counts`.

## Ограничения от спама

- писать могут только вошедшие;
- до 500 символов, не чаще раза в 15 секунд и не больше 60 в сутки на человека;
- только к играм, которые есть в `games.json`;
- текст выводится как текст: ссылки и разметка не оживают.

## Модерация

Модератор видит «Delete» под любым комментарием и очередь присланных игр.
В Telegram приходят уведомления о новых заявках на игры. Как назначить
модератора — в закрытой документации (раздел BACKEND).

Забанить человека:

```sh
npx wrangler d1 execute plair-counts --remote --command "SELECT id, name, login FROM users ORDER BY created DESC LIMIT 20"
npx wrangler d1 execute plair-counts --remote --command "UPDATE users SET banned = 1 WHERE id = 'github:12345'"
```

## Запросы

| запрос | что делает |
|---|---|
| `GET /counts` | все счётчики разом, минута кэша |
| `POST /play` `{id, visitor}` | засчитывает запуск, не чаще 10 раз в сутки с браузера на игру |
| `POST /like` `{id, visitor, on}` | лайк, один с браузера на игру |
| `POST /share` `{id, visitor}` | репост, один в сутки с браузера на игру |
| `POST /skip` `{id, visitor}` | скип: игру закрыли быстрее 10 секунд после запуска; один в сутки с браузера на игру |
| `POST /time` `{id, visitor, seconds}` | секунды в игре: до 60 за запрос, до 30 минут в сутки с браузера на игру |
| `GET /config` | какие входы настроены |
| `POST /score` `{id, visitor, value, lower}` | счёт партии из PLAIR SDK; хранится лучший, до 60 в сутки с браузера на игру |
| `GET /board?game=…&visitor=…` | таблица рекордов: топ-10 и моё место |
| `POST /duel` `{id, visitor, value}` → `{code}` | ссылка «побей мой рекорд» (`/?g=игра&duel=код`) |
| `GET /duel/:code` | чей это вызов и какой счёт побить |
| `POST /verify` `{url}` | «это моя игра»: вход через GitHub (для name.github.io) или код `plair-…` на странице игры / в `plair.txt` |
| `POST /submit` | заявка на игру; без доказательства авторства и тяжелее 10 МБ — отказ |
| `POST /auth/google/token` `{credential}` | вход через Google: паспорт → пропуск |
| `GET /auth/github?back=…` | вход через GitHub; возвращает на `back` с пропуском |
| `GET /me` | кто вошёл |
| `DELETE /me` | стереть свои комментарии и запись о себе |
| `GET /comments?game=…&before=…` | комментарии к игре, по 20, новые сверху |
| `POST /comments` `{game, text}` | написать |
| `DELETE /comments/:id` | удалить свой (или любой — модератору) |

Чужие сайты Worker не обслуживает: запросы принимаются только с
`plair.pro` и `www.plair.pro`, и вернуть после входа он может только туда.

```sh
printf 'SESSION_SECRET=test\nEXTRA_ORIGINS=http://localhost:8080\nCATALOG=http://localhost:8080/games/games.json\n' > .dev.vars
npx wrangler dev
```
